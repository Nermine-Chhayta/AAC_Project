# Module 5 AI Governance Retrospective Worksheet

Use this worksheet to review your own AI-assisted work honestly. Replace each example row with notes from your actual project, prompts, code reviews, commits, or reflection logs. Do not guess, polish, or fill gaps with what "probably" happened.

For each table:

- Be specific enough that future-you can understand what happened.
- Mark uncertainty clearly instead of pretending you know.
- Do not mark everything "Low" just because the project feels small. A small course project can still include private repo context, secrets, copied code, or data that should not have been shared.
- Leave a row blank until you have evidence from notes, code, commits, or memory you trust.

## 1. What I Shared

Risk rubric:

- Low: public code, course toy project code, no sensitive data, no proprietary logic.
- Medium: private but non-sensitive code, internal implementation details, non-public repo context with no secrets/PII.
- High: credentials, tokens, secrets, production config, real customer/user data, regulated data, unauthorized code.
